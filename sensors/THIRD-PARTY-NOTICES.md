# Third-party sensor components

WinMemoryCleaner Community's optional isolated sensor backend uses the following unmodified, pinned binary components. `dependencies.lock.json` records package hashes and selected Windows x64 runtime file hashes. Own backend source retains this repository's license and C#4/analyzer requirements; third-party binary source is not represented as satisfying our legacy compiler rules.

Full MPL-2.0, .NET MIT, HidSharp notices, PawnIO GPLv2 and LGPLv2.1 texts, and the complete PawnIO linking exception are embedded with the payload. The exception permits independently licensed programs communicating solely through IOCTL; **it does not exempt modules loaded over the Pawn interface**. The retained corresponding-source bundle includes the 2.1.0 driver/API/tool, its separately pinned PawnPP submodule and the unchanged 0.2.2 module sources/compiler inputs. It does not claim to contain the 2.2.0 driver sources: the optional 2.2.0 installer is obtained directly from the vendor, and its exact public driver source is linked above. Source correspondence does not imply a bit-identical signed rebuild; official signing credentials and the installer wrapper source are not available.

System.Management and System.CodeDom NuGet inputs are restored and pinned to resolve the package graph, but their package DLLs are not shipped: the .NET Framework System.Management implementation and its framework dependencies are used. The storage-only DiskInfoToolkit binary is recorded under `excludedAssets` and is not shipped. The pinned LHM CPU/GPU-only profile never enables storage; the other runtime libraries remain included. No existing sensor settings or saved software-control modes are loaded.

The signed installer is not embedded in the runtime payload. Only after explicit installation confirmation does the application acquire the pinned official package from its fixed GitHub source, or copy a user-selected local offline package. Length, SHA256, Authenticode and signer identity are verified, and the verified file is held read-only until the installer exits. The independent installer cache is not needed by normal monitoring. No unrestricted build, silent install, automatic reboot, fan/power/voltage control, scheduled sampling task or sampling service is included. Installing the official shared kernel driver can require elevation/reboot; existing third-party/shared drivers are never overwritten by this application. Hardware acquisition may use read/write-capable native handles/IOCTLs to perform required measurement operations; this is not a claim that every underlying IOCTL has read-only access bits.
