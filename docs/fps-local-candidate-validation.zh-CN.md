## 保留的失败与修正轨迹

1. **FPS 发布槽**：旧回调排队时会丢弃已采集的新读数，旧回调又因代次过期被拒绝。新增确定性用例曾在旧逻辑上出现预期 `72`、实际 `—` 的断言失败。当前逻辑保留一个排队回调，用最新当前样本替换待发布数据，仍校验需求及 FPS 目标代次，并在处置时清空；没有增加采样或修改调度器。
2. **折叠详情**：安装器来源说明仍位于预期的默认折叠详情中。窗口用例先验证默认折叠，再显式展开并执行原有来源断言，未删除说明或放宽断言。
3. **进程 Loading 时序**：旧用例恢复读取后，测试替身仍返回失败，Dispatcher 可以合法地先发布 Failed，再执行瞬态 Loading 断言。原二进制独立复现与完整回归均保留这次断言失败。修正仅在测试替身加入读取门：读取进行中验证 Loading，再释放成功空列表，通过实际采样与 UI 发布链路验证结果；`finally` 释放门并等待监控器恰好处置一次。没有为此修改生产状态机。
4. 临时运行器曾因 Desktop 逐测试超时破坏 Dispatcher 线程约束；相应历史失败保持失败，不移作业务 RED。本次所有桌面运行均使用单 STA。证据复算也已验证：旧失败回归会被拒绝，不生成通过报告。

此前的失败构建、测试结果与性能记录未覆盖或改记为通过。本次续接保留了既有工作树；除上述授权窗口测试差异外，其余继承文件逐字节未变。
