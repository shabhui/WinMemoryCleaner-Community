# WinMemoryCleaner 社区版 · 资源监控与进程管理使用指南

本指南说明社区版新增的按需资源监控、进程占用定位、安全进程操作、可选悬浮监控与可选游戏 FPS。原有内存清理、托盘、快捷键、设置、明暗主题与语言能力全部保留，使用方式不变。

本指南按当前源码说明功能，**不表示当前候选已发布或全部验收通过**。正式下载请使用[社区 Releases](https://github.com/shabhui/WinMemoryCleaner-Community/releases/latest)；当前 p3 开启提示与官方 PawnIO 2.2.0 支持见[p3 历史记录](cpu-driver-prompt-report.zh-CN.md)。旧 `3.0.8.4-community.4` 发布证据见[通用温度历史记录](universal-temperature-report.zh-CN.md)，不能移作本次候选的 CI 或性能结果。本文 `build/...` 仅为相对仓库根的本地证据位置，不随发布公开，不嵌入原始截图、日志或个人配置。

快速使用：从旧版托盘菜单自行退出程序，再运行新版 EXE → **设置 → 悬浮监控** → 勾选需要的显示项（温度需单独勾选）→ 排列方式选横向/竖向 → 点击 **仅显示监控条**。点击托盘图标可重新打开主窗口和设置。程序是单实例，旧版未退出时不能把第二次启动当作新版验收。

## 运行要求

- 主 WPF / .NET Framework 4.0 程序保持原有兼容性；通用温度后端的目标为 **Windows 10/11 x64 + .NET Framework 4.7.2 或更新的 4.x**。缺少后端运行时/架构支持时诚实降级，不自动安装 .NET。
- 程序需要管理员权限（与原版一致，用于内存清理与进程工作集操作）；传感器权限仍可能独立受限。
- 下载仍是单个 `WinMemoryCleaner.Community.exe`，无需在旁边放 DLL。可见概览/进程页会请求温度；仅悬浮显示时按温度显示项决定。缺少轻量来源时按需释放内嵌组件到 `%LOCALAPPDATA%\WinMemoryCleaner.Community\Sensors` 的校验版本目录，最多一个自有后端，另有缓存/进程内存成本。
- 对应源码包与完整许可说明见[第三方通知](../sensors/THIRD-PARTY-NOTICES.md)和[源码说明](../sensors/SOURCE-README.md)。保留档案包括 PawnIO **2.1.0** 驱动/API/工具、独立 PawnPP、模块 **0.2.2** 源码/编译器输入；外部 **2.2.0** 驱动只提供精确公开源码链接，不把它误称为已打包档案。官方安装器外壳源码和签名凭据未提供，不承诺逐字节重建签名安装器。

## 主界面概览（监控页）

打开主窗口即显示资源概览：

- **内存仪表**：显示物理内存占用比例与已用/总量，避免展开页和底部重复大卡片；紧凑模式保留实时用量摘要。
- **CPU / GPU 读数**：成对显示整机 CPU 使用率与 GPU 使用率（取最繁忙的物理显卡引擎），温度紧邻对应使用率。常驻说明精简，长来源、统计口径与限制收进默认折叠的**详情**或读数提示，不删除信息。
- **温度**：先复用已有 ASUS CPU / NVIDIA NVAPI 来源，再尝试已运行的默认名 LHM/OHM WMI；缺少指标时才按需启动内嵌 LibreHardwareMonitor 0.9.6 后端。可用指标不被后续来源覆盖，轻量来源完全覆盖时无需保持后端运行。详情标明真实提供者、传感器及失败原因；**没有可信读数时显示 —**，不以热点、显存、ACPI 区域或距离阈值冒充核心，不显示虚假 0°C。

### 刷新间隔

支持 **1、2、5 秒** 三档，默认 **2 秒**。可在设置页的监控分区修改。

### 关于"不可用"

监控坚持诚实显示：权限受限、驱动不支持、无来源或读取失败时，不把未知数据当作 0。概览的温度、FPS 及监控条不可用项显示 **—**；CPU/GPU 使用率仍可显示预热或不可用文案。原因在读数提示、概览“详情”或设置状态行查看。进程页不可用值排在最后，不参与数值比较。

## 可选游戏 FPS（默认关闭）

1. 在概览勾选 **FPS**，或在设置的显示项中勾选**游戏 FPS（提交）**。显示开关与监控条开关独立：需要游戏窗口上方的读数时，另行开启监控条并保留 FPS 显示项。
2. **自动跟随前台**：跟随当前前台窗口所属程序，排除本工具。不会为寻找前台而枚举整个进程列表。
3. **手动选择进程**：点“选择游戏 / 进程…”进入进程页，选中游戏后点**选为 FPS 目标**。只高亮另一行不会切换；该操作只设置目标，不会自动开启 FPS。陈旧或失败的进程列表不能设置新目标。
4. 手动目标复制 PID、创建时刻和显示名称，只在本次运行中保留；采集端用只读查询验证身份。退出、PID 复用或无法验证时显示实际状态，游戏或本工具重启后需要重新选择；可在设置清除目标或切回自动模式。

FPS 统计经验证格式的 **DirectX DXGI / D3D9 成功 Present 提交速率**，不是屏幕 Hz、软件界面刷新次数、上屏帧率或补帧结果。多个交换链不相加。开始后需至少两个可信事件才可能有数值；没有近期帧、权限不足、系统/接口不支持、格式未知或事件丢失时显示 **—** 与实际原因，不伪造 0/60。

采集只使用自有、按目标进程和事件过滤的 Windows ETW 实时会话，不注入、不 hook、不安装新组件或驱动、不操作其他工具的会话。不支持过滤或事件格式时诚实降级，不回退到全系统捕获。默认关闭且没有可见需求时，不分配原生采集资源或启动采集线程。

FPS 仅在可见概览或启用的监控条需要它时采集。没有监控条需求的进程页、设置页、紧凑模式，以及隐藏/最小化主窗口均暂停；关闭显示或切换目标立即清空旧读数，后台串行停止自有采集，不在 UI 等待。

**尚未实测的边界：** 本次新 FPS 的原生 ETW 路径与真实游戏尚未完成验收，不承诺 OpenGL/Vulkan、独占全屏、反作弊应用、上屏帧或帧生成覆盖。确定性替身测试不能替代真实采集准确性和资源开销验证；原 Community.5 发布性能门槛仍未通过，功能说明不等于放行发布。

## 进程占用列表（进程页）

- 列出**当前可枚举的全部进程**，同名进程保留独立 PID 行。
- 列：名称、PID、内存、CPU（全机归一化）、GPU 使用率、显存占用（系统与驱动支持时显示）。
- **搜索**：支持按名称或 PID 模糊匹配。
- **排序**：点击列头可按内存、CPU、可用 GPU 指标升/降序排序，不可用值始终排最后。
- 权限受限或采样期间退出的进程不会导致列表崩溃，对应行会移除或标注不可用。

### 进程操作（两项独立操作）

选中进程后：

1. **释放工作集**：要求系统释放所选进程的工作集内存。这只是让系统把该进程的物理内存页换出/回收，进程继续运行；不保证降低其 CPU/GPU 占用，也不承诺提高游戏帧率。
2. **结束进程**：弹出确认对话框，明确显示**目标进程名称、PID 与"未保存数据可能丢失"警告**；只有点击确认才执行，**取消不执行任何操作**。

安全防护（内置，不可绕过）：

- 拒绝对工具自身、系统关键进程与受保护进程的操作。
- 身份校验与实际操作使用**同一个原生进程句柄**，防止同名或 PID 复用把动作指向另一进程；仍需用户确认所选目标，不能消除普通应用误操作的风险。
- 无法确认安全身份时拒绝操作并明确报错。

## 悬浮监控（默认关闭）

在设置页开启“悬浮监控”后，显示独立的**紧凑监控条**，不再使用固定宽度的大面板：

- **排列**：默认横向一行，CPU / GPU 的温度紧邻对应使用率；可切换竖向，FPS 开启后增加独立组，选择会保存。旧紧凑条版本的全部显示项实测为横向 **316×26 DIP**、竖向 **118×78 DIP**（系统 DPI 会影响实际屏幕像素），不包含当前新增 FPS，也不是当前候选的新测量。没有外层大底框、常驻标题、阴影或长说明。
- **仅显示监控条**：点击同名按钮启用监控条并隐藏主窗口，保留托盘入口。不会改变原有关闭按钮偏好；保存为开启时，即使下次隐藏主窗口启动，也会恢复监控条。
- **不抢焦点**：开启时不激活；独立置顶，默认鼠标穿透，不影响下面的应用操作。
- **位置**：可选择显示屏与四个角落，也可点击“拖动定位”调整位置；位置保存，屏幕失效或坐标离屏时恢复到可见区域。横竖切换及语言切换不会重置已选布局。
- **显示项**：可分别勾选 CPU 使用率、GPU 使用率、内存、CPU 温度、GPU 温度、游戏 FPS。全新设置默认只勾选使用率和内存，温度与 FPS 均需显式开启；保留已有用户选项，不擅自重置。FPS 也可以作为监控条唯一显示项。
- 拖动定位时临时接受输入，短提示只在拖动模式出现；松开或 30 秒超时后恢复鼠标穿透偏好。
- 历史报告在普通窗口与无边框全屏窗口验证过可见性与穿透性，不能替代当前候选的新验证。**不覆盖独占全屏游戏、受保护应用或特殊反作弊环境**（不在保证范围内，也不做任何注入或绕过）。

关闭悬浮层并隐藏主窗口后，程序**停止无消费者的 CPU/GPU、温度与进程详情采样**，仅保留托盘内存显示与自动清理策略所需的最低限度监测（5 秒节奏）。重新打开窗口立即恢复采样。

## 温度来源说明

- **按需通用来源**：固定 LibreHardwareMonitorLib **0.9.6**，只启用 CPU/GPU 类别；不需另开 LHM。CPU 按 Package→Tdie→Tctl/Tdie 合并→Die average→CCD最高→Core最高选择，具体含义会注明，不推算偏移。GPU 只选有效核心温度，多设备取最高有效代表值。所有读数须有限且 **1–150°C**。
- **驱动信任与品牌限制**：通用 CPU 需父/子两端精确核对官方标准 PawnIO **2.1.0 / 2.2.0** 的版本/哈希、Windows 签名信任和设备就绪；任意更新版本或仅签名有效不足以放行。不明共享驱动不误报缺失，也不覆盖/降级。固定 LHM 的 Intel GPU 分组依赖 CPU 分组，因此受同一门控；NVIDIA/AMD GPU 独立探测。不是全硬件兼容保证。
- **显式确认与离线入口**：日常启动/监控不下载安装器。用户显式开启 CPU 温度或包含 CPU 温度的悬浮显示时异步检查，确切缺失才询问安装；权限受限/设备未就绪/无法验证只说明原因。明确确认后才准备固定[官方 PawnIO **2.2.0**](https://github.com/namazso/PawnIO.Setup/releases/tag/2.2.0)，可下载或选择本地离线包。两者同样验证长度、SHA-256、Authenticode、签名者、路径及只读租约。取消选择直接返回，无效离线包不回退联网，准备可取消；不静默安装、不强杀已启动安装器、不自动重启、不替换/卸载共享驱动、不关闭 Secure Boot/HVCI。某硬件成功读温度不等于真实安装器执行已验收。
- **轻量来源**：CPU 可复用 ASUS System Control Interface 传感器 **0x00120094**，GPU 可复用 NVIDIA NVAPI，再尝试已运行的默认名 LibreHardwareMonitor / OpenHardwareMonitor WMI。来源独立探测并有 **30 秒**失败退避，改名提供者可能无法识别。已有来源缺失并不等于软件或驱动未安装。
- **生命周期与失败**：刷新1/2/5秒；子进程启动后首帧最多10秒，载荷解包不消耗握手预算；年龄上限为 `max(10秒,3×刷新间隔)`，故障30秒后重试。重复/陈旧/未来帧不续命；关闭温度需求、暂停或退出立即撤销缓存，后台先发送stop并最多等待2秒，再终止无响应的所属子进程，不阻塞 UI。主窗隐藏但条仍需要温度时继续。上游测量可使用读写权限的句柄/IOCTL，自有代码不调用风扇、功耗、电压、超频或性能模式控制接口。

## 常见问题

- **CPU 温度为 — / 不可用？** 在资源概览与设置状态行查看具体原因。已有受支持 ASUS 驱动可走备用；通用 CPU 要求可信标准 PawnIO，就绪后才能读取。没有授权不会安装；已有共享/未知版本不会被覆盖。也可自行运行受支持的默认名 LHM/OHM WMI 提供者后等待重试，仍无可信来源则保持 —。
- **GPU 使用率显示为不可用或等待中？** 首次采样需要两帧数据；虚拟显示适配器（如模拟器虚拟显卡）已被排除，仅统计物理显卡。
- **FPS 显示 —？** 查看目标和状态。手动模式需要显式选择仍有效的游戏进程；自动模式需要切到游戏窗口。没有近期成功 Present、权限不足或接口/事件格式不支持都不会提供伪造数值。真实 ETW/游戏覆盖仍待验收，不建议关闭系统保护或绕过反作弊来强行取得读数。
- **释放工作集后内存没降？** 工作集释放只影响所选进程的驻留内存；若进程仍在活跃分配，数值会再次上升。
- **仅显示监控条后怎样改设置？** 点击托盘图标重新打开主窗口。右上角“紧凑模式”是原清理窗口的精简模式，不等同于监控条独显。
- **运行新版却还是旧界面？** 两版共享单实例身份，请先自行从旧版托盘退出再运行新版。是否调整开机任务或替换旧文件由用户决定，不要把重复启动当作新版验收。
