# WinMemoryCleaner 社区版 · 资源监控与进程管理使用指南

本指南说明社区版新增的轻量资源监控、进程占用定位、安全进程操作与可选悬浮监控。原有内存清理、托盘、快捷键、设置、明暗主题与语言能力全部保留，使用方式不变。

**通用温度新版（尚未发布）**：本指南包含已实现、仍在验收的 `3.0.8.4-community.4` 功能；当前 [Releases/latest](https://github.com/shabhui/WinMemoryCleaner-Community/releases/latest) 仍为旧版。新版只会在全部发布门禁通过后提供 CI 构建 EXE；进度见 [通用温度验收记录](universal-temperature-report.zh-CN.md)。[2026-10-17 紧凑条报告](compact-monitoring-report.zh-CN.md)及其中便携 EXE/截图均为旧版历史资料，不代表通用后端新版。

快速使用：从旧版托盘菜单自行退出程序，再运行新版 EXE → **设置 → 悬浮监控** → 勾选需要的显示项（温度需单独勾选）→ 排列方式选横向/竖向 → 点击 **仅显示监控条**。点击托盘图标可重新打开主窗口和设置。程序是单实例，旧版未退出时不能把第二次启动当作新版验收。

## 运行要求

- 主 WPF / .NET Framework 4.0 程序保持原有兼容性；通用温度后端的目标为 **Windows 10/11 x64 + .NET Framework 4.7.2 或更新的 4.x**。缺少后端运行时/架构支持时诚实降级，不自动安装 .NET。
- 程序需要管理员权限（与原版一致，用于内存清理与进程工作集操作）；传感器权限仍可能独立受限。
- 下载仍是单个 `WinMemoryCleaner.Community.exe`，不用在旁边放 DLL。温度启用时按需解出内嵌组件到 `%LOCALAPPDATA%\WinMemoryCleaner.Community\Sensors` 的校验版本目录，最多启动一个专属后端；带来额外 EXE/缓存大小与后台进程内存开销。
- 发布另附固定哈希对应源码 ZIP（PawnIO 驱动/API/工具、独立 PawnPP 子模块、模块0.2.2源码及编译器输入），便携 ZIP 含六份完整许可和第三方说明。官方签名安装器外壳源码及签名凭据未公开，源码包不承诺逐字节重建签名安装器。

## 主界面概览（监控页）

打开主窗口即显示资源概览：

- **内存仪表**：横向主仪表显示物理内存占用比例，附已用/可用数值。
- **CPU / GPU 读数**：成对显示整机 CPU 使用率与 GPU 使用率（取最繁忙的物理显卡引擎），并标注数据来源（Windows GetSystemTimes / Windows PDH）。
- **温度**：先自动尝试内嵌 LibreHardwareMonitor 0.9.6 后端，CPU/GPU 独立降级到已有 ASUS CPU 传感器、NVIDIA NVAPI、已运行的 LHM/OHM WMI。详情标明真实提供者、设备、传感器与失败原因。**没有可信读数时显示“不可用”及原因**，不以热点、显存、ACPI 区域或距离阈值冒充核心，不显示虚假的 0°C。

### 刷新间隔

支持 **1、2、5 秒** 三档，默认 **2 秒**。可在设置页的监控分区修改。

### 关于"不可用"

监控坚持诚实显示：权限受限、驱动不支持、无传感器来源或读取失败时，主界面显示“不可用”及具体原因。监控条为避免撑大尺寸，预热/不可用项只显示 **—**；这不是 0，原因可在资源概览查看。进程页不可用值排在最后，不参与数值比较。

## 进程占用列表（进程页）

- 列出**当前可枚举的全部进程**，同名进程保留独立 PID 行。
- 列：名称、PID、内存、CPU（全机归一化）、GPU 使用率、显存占用（系统与驱动支持时显示）。
- **搜索**：支持按名称或 PID 模糊匹配。
- **排序**：点击列头可按内存、CPU、可用 GPU 指标升/降序排序，不可用值始终排最后。
- 权限受限或采样期间退出的进程不会导致列表崩溃，对应行会移除或标注不可用。

### 进程操作（两项独立操作）

选中进程后：

1. **释放工作集**：要求系统释放所选进程的工作集内存。这只是让系统把该进程的物理内存页换出/回收，进程继续运行；不保证降低其 CPU/GPU 占用，也不承诺提高游戏帧率。
2. **结束进程**：弹出确认对话框，明确显示**目标进程名称、PID 与"未保存数据可能丢失"警告**；只有点击确认才执行，**取消不执行任何操作**。

安全防护（内置，不可绕过）：

- 拒绝对工具自身、系统关键进程与受保护进程的操作。
- 身份校验与实际操作使用**同一个原生进程句柄**，杜绝同名进程与 PID 复用导致的误操作。
- 无法确认安全身份时拒绝操作并明确报错。

## 悬浮监控（默认关闭）

在设置页开启“悬浮监控”后，显示独立的**紧凑监控条**，不再使用固定宽度的大面板：

- **排列**：默认横向一行，CPU / GPU 的温度紧邻对应使用率；可切换竖向三组，选择会保存。全部显示项的本次实测为横向 **316×26 DIP**、竖向 **118×78 DIP**（系统 DPI 会影响实际屏幕像素）。没有外层大底框、常驻标题、阴影或长说明。
- **仅显示监控条**：点击同名按钮启用监控条并隐藏主窗口，保留托盘入口。不会改变原有关闭按钮偏好；保存为开启时，即使下次隐藏主窗口启动，也会恢复监控条。
- **不抢焦点**：开启时不激活；独立置顶，默认鼠标穿透，不影响下面的应用操作。
- **位置**：可选择显示屏与四个角落，也可点击“拖动定位”调整位置；位置保存，屏幕失效或坐标离屏时恢复到可见区域。横竖切换及语言切换不会重置已选布局。
- **显示项**：可分别勾选 CPU 使用率、GPU 使用率、内存、CPU 温度、GPU 温度。全新设置默认只勾选使用率和内存，保留已有用户选项，不擅自重置。
- 拖动定位时临时接受输入，短提示只在拖动模式出现；松开或 30 秒超时后恢复鼠标穿透偏好。
- 已通过普通窗口与无边框全屏窗口验证可见性与穿透性。**不覆盖独占全屏游戏、受保护应用或特殊反作弊环境**（不在保证范围内，也不做任何注入或绕过）。

关闭悬浮层并隐藏主窗口后，程序**停止无消费者的 CPU/GPU、温度与进程详情采样**，仅保留托盘内存显示与自动清理策略所需的最低限度监测（5 秒节奏）。重新打开窗口立即恢复采样。

## 温度来源说明

- **通用优先来源**：固定 LibreHardwareMonitorLib **0.9.6**，只启用 CPU/GPU 类别；无需另开 LibreHardwareMonitor。CPU 按 Package→Tdie→Tctl/Tdie 合并→Die average→CCD最高→Core最高六级规则选择；合并/平均/CCD/核心含义在详情注明，不推算偏移。GPU 只选有效核心温度，多设备显示最高有效代表值。所有读数必须有限且 **1–150°C**。
- **驱动信任与品牌限制**：通用 CPU 只在父/子两端验证固定官方标准 PawnIO **2.1.0** 镜像、Windows 签名信任、版本与设备就绪后启用。其他共享/更新/无法确认模式的驱动保持不可用，但不能误报“未安装”，也不覆盖或降级。固定 LHM 的 Intel GPU 分组依赖 CPU 分组，因此也受此可信门控；NVIDIA/AMD GPU 可独立探测。不保证所有硬件、虚拟机或安全策略环境都有温度。
- **显式安装入口**：设置中的状态一行和“安装通用温度驱动”按钮不会自行安装；点击后必须先明确确认，才启动已校验签名的官方交互安装器。取消不安装。已有共享驱动不会被替换；失败、受阻或需要重启只提示原因，不关闭 Secure Boot/HVCI、不自动重启、不卸载共享驱动。本次开发/测试没有执行安装器，真实通用 CPU 实机验证仍缺用户授权。
- **逐指标备用**：CPU 可使用已安装 ASUS System Control Interface 传感器 **0x00120094**；GPU 可使用已安装 NVIDIA NVAPI；再尝试已运行的默认名 LibreHardwareMonitor / OpenHardwareMonitor WMI，两者独立探测和30秒失败退避。改名提供者可能无法识别。旧 ROG G834JZ/i9-13980HX 的52→59°C属于 ASUS历史证据，不是新版通用 CPU 实测。
- **生命周期与失败**：刷新1/2/5秒；子进程启动后首帧最多10秒，载荷解包不消耗握手预算；年龄上限为 `max(10秒,3×刷新间隔)`，故障30秒后重试。重复/陈旧/未来帧不续命；关闭温度需求、暂停或退出立即撤销缓存，后台先发送stop并最多等待2秒，再终止无响应的所属子进程，不阻塞 UI。主窗隐藏但条仍需要温度时继续。上游测量可使用读写权限的句柄/IOCTL，自有代码不调用风扇、功耗、电压、超频或性能模式控制接口。

## 常见问题

- **CPU 温度为 — / 不可用？** 在资源概览与设置状态行查看具体原因。已有受支持 ASUS 驱动可走备用；通用 CPU 要求可信标准 PawnIO，就绪后才能读取。没有授权不会安装；已有共享/未知版本不会被覆盖。也可自行运行受支持的默认名 LHM/OHM WMI 提供者后等待重试，仍无可信来源则保持 —。
- **GPU 使用率显示为不可用或等待中？** 首次采样需要两帧数据；虚拟显示适配器（如模拟器虚拟显卡）已被排除，仅统计物理显卡。
- **释放工作集后内存没降？** 工作集释放只影响所选进程的驻留内存；若进程仍在活跃分配，数值会再次上升。
- **仅显示监控条后怎样改设置？** 点击托盘图标重新打开主窗口。右上角“紧凑模式”是原清理窗口的精简模式，不等同于监控条独显。
- **运行新版却还是旧界面？** 两版共享单实例身份。请自行从旧版托盘菜单退出后再运行新路径；本次没有更改开机启动计划任务或覆盖旧 EXE。
