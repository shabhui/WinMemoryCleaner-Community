# 托盘与监控刷新优化验证报告

范围：既有刷新热路径优化及相关回归的去标识化历史记录。本次文档整理不重跑验证；以下 `build/...` 相对仓库根，**仅本地留存、不随发布公开**。截图、原始日志及个人环境内容不嵌入公开说明；历史清单仍对应原报告字节。

**结论：本轮实现、构建和相关回归完成；原始目标尚未全部验收。正式体积上限已经实测不达标，标准时长的完整性能验收尚未运行。**

## 1. 范围与基线

- 仅在获准的社区工作树开展当时的验证，未操作其他副本。
- 本轮性能增量基线：`e476d2d` 改动前保存的 Test / Release 构建。它不是原始目标规定的正式基线。
- 原始目标正式基线：`da2cf8b`。本轮另外从该提交归档源码、使用相同工具链完成 Release 构建，**仅用于体积比较**，未对它运行正式性能对比。
- 使用系统 Framework64 `v4.0.30319` MSBuild/C# 编译器和仓库 net40 reference assemblies，保留主程序 .NET Framework 4.0 / C# 4 约束。实际运行 CLR 为 `4.0.30319.42000`；未在纯 .NET 4.0 系统上重新验证兼容性。既有独立传感器后端及其运行时要求没有改变。
- 不降低监控采样频率，不改变主题、语言、原清理策略或更新通道，不增加依赖，不建立多图标缓存。
- 未提交、推送、发布或签名。本报告不是 CI 发布证明。

## 2. 实现

### 托盘

[NotificationService.cs](../src/Service/NotificationService.cs) 捕获最终数字、有效颜色、透明背景、清理状态和提示文字：

- 相同状态不重复绘制或派发 UI 工作；仅 tooltip 变化时不替换图标。
- UI 忙碌时至多保留一个待应用图标和一个待执行回调，后续状态覆盖待处理状态。
- 明确当前图标与待处理图标的所有权；覆盖、派发取消、异常和关闭路径释放相应资源。
- 保留异步 UI 派发、防死锁行为和清理旋转动画；切回数字图标时停止旋转。

### 监控显示

[MonitoringViewModel.cs](../src/ViewModel/MonitoringViewModel.cs) 先发布完整显示快照，再按最终文字差异通知绑定：

- 主界面与悬浮层按各自精度比较；重复读取数值文字复用格式化结果。
- 语言切换、采样发布及温度停采时刷新显示快照。
- 内存文字和驱动安装状态 getter 保持实时，避免后台状态被冻结；只缓存其通知比较值。
- 刷新选项 `[1, 2, 5]` 共享只读集合。

相关新增测试：[MonitoringRefreshTests.cs](../src/Test/MonitoringRefreshTests.cs)、[NotificationRefreshTests.cs](../src/Test/NotificationRefreshTests.cs)。源码链接指向当前工作树，不能替代历史输入冻结记录。

## 4. 固定输入微基准

工具：[RefreshHotPathProbe.cs](../tools/RefreshHotPathProbe.cs)、[verify-refresh-hotpaths.ps1](../tools/verify-refresh-hotpaths.ps1)。

两版顺序交替运行三轮，每项取三轮中位数。仅接受隔离的 `CommunityTestBuild` 程序集，无可见系统托盘图标，不启动监控采样，不执行强制 GC 或工作集清空。托管分配使用 `AppDomain.MonitoringTotalAllocatedMemorySize`。

| 固定输入 | 次数/轮 | 耗时：改动前 → 改动后 | 托管分配字节：前 → 后 | 图标替换：前 → 后 |
|---|---:|---:|---:|---:|
| 稳定托盘状态 | 3,000 | 759.412 → 1.553 ms | 4,956,864 → 966,656 | 3,000 → 0 |
| 仅 tooltip 改变 | 3,000 | 667.211 → 1.895 ms | 4,958,336 → 1,351,680 | 3,000 → 0 |
| 重复读取 `CpuText` | 100,000 | 18.465 → 0.138 ms | 8,026,112 → 0 | 不适用 |

- 稳定托盘路径分配减少 **80.5%**，tooltip-only 路径减少 **72.7%**。
- 重复读取 CPU 显示文字的可测分配为 0；不是“整个监控无分配”。
- 优化后这些测量段均未发生 GC；改动前稳定托盘段 Gen0 中位数为 1，getter 段 Gen0 / Gen1 中位数为 2 / 1。
- 这是人为放大调用次数的局部测量，**不能将耗时百分比解释成软件整体 CPU、内存或游戏性能的提升比例**。

## 5. 真实窗口短测（不是正式性能验收）

- Windows 验证环境，同工具链 Release；具体系统构建号及硬件配置不公开。
- 固定隔离测试条件：简体中文、深色、14pt、默认监控间隔 **2 秒**，不是用户个人配置。前后两版各依次运行托盘、主界面、进程页、悬浮层。
- 每状态 **预热 5 秒、测量 15 秒、1 轮**，每轮 15 个测量样本。截图另行运行，不混入本表。
- CPU 按进程 CPU 时间 / 实际单调时长 / 逻辑处理器数归一化。内存列为测量段私有字节中位数，不是工作集。
- **本工具统计主宿主进程，未合计独立温度后端子进程。** 因此不能据此宣称整个应用符合正式占用上限。

| 状态 | 平均自身 CPU %：前 → 后 | 私有内存 MiB：前 → 后 | 调度 P95 ms：前 → 后 |
|---|---:|---:|---:|
| 托盘、悬浮关闭 | 0.08323 → 0.01560 | 60.160 → 59.016 | 1.103 → 0.864 |
| 主界面监控 | 0.05187 → 0.02070 | 64.477 → 64.977 | 0.674 → 1.129 |
| 进程页 | 0.26499 → 0.26497 | 72.875 → 70.957 | 70.935 → 1.101 |
| 悬浮监控 | 0.02593 → 0.02073 | 61.727 → 61.836 | 0.900 → 1.287 |

主窗口私有内存比本轮基线高 0.5 MiB；托盘低约 1.145 MiB。真实进程数从基线的 439–441 条变为优化版的 433–436 条，说明两段测量并非完全冻结的相同负载；不能把单轮差异都归因于本次代码优化。

两版的总/进程/温度采样计数分别相同：托盘 `1/0/1`、主界面 `11/0/11`、进程页 `12/11/12`、悬浮层 `13/0/2`，没有通过降低采样频率换取本轮结果。计数包含窗口初始化阶段，不应把托盘的首个初始化样本当成持续后台采样。

已从八组原始 `samples.csv` / `dispatcher.csv` 重算样本数、私有内存中位数与增长、最近秩 P95、进程行数及测量时长，并核对时间加权 CPU（CSV 舍入容差 0.001 个百分点）。

本地短测证据：`build/refresh-optimization/window-smoke/{baseline,optimized}/medians.json` 及 `optimized/process-1/samples.csv`；同一证据树保留全部原始 CSV、JSON 和日志。
